## 1. 设计总览

### 1.1 设计原则

| 原则 | 说明 |
|------|------|
| **MVP 优先** | Phase 1 只做单人跑团闭环，不建 IM/好友系统 |
| **渐进架构** | 单人模式代码不耦合多人逻辑，但预留扩展点 |
| **服务分离** | Go（业务+实时通信）+ Python（AI+向量检索），职责清晰 |
| **同步调用** | MVP 阶段 Go↔Python 走 HTTP，不引入消息队列 |
| **流式优先** | AI 推理结果通过 WebSocket 流式推送到前端 |
| **无状态 Go** | Go 服务不持有会话状态，状态全部外存到 Redis/PostgreSQL |

### 2.5 WebSocket 客户端

```
连接生命周期:
  1. 登录成功 → 获取 JWT Token
  2. 建立 WebSocket: wss://host/ws?token=<JWT>
  3. 服务端验证 Token → 绑定 user_id → 发送 `connected` 确认
  4. 心跳: 客户端每 30s 发送 Ping, 服务端回复 Pong
  5. 断线: 指数退避重连 (1s→2s→4s→8s→16s→30s 封顶)
  6. 重连成功: 发送 `sync` 消息, 服务端补推离线期间消息

消息类型 (JSON):
{
  "type": "game_action" | "game_narrative" | "dice_roll" | "status_update"
         | "system" | "ping" | "pong" | "sync" | "error",
  "payload": { ... },
  "timestamp": "ISO8601",
  "seq": 123           // 单调递增序号, 用于断线补推
}
```

```python
class ChunkStrategy:
```

### 4.3 RAG 检索实现

```python
# services/retriever.py
class RAGRetriever:
    def retrieve(
        self,
        query: str,                    # 当前玩家行动 + 上下文摘要
        top_k: int = 20,               # 初检数量
        final_k: int = 5,              # MMR 后返回数量
        lambda_param: float = 0.7,     # MMR λ 参数
    ) -> list[ScriptChunk]:
        """
        1. 将 query 向量化
        2. Milvus.search() → Top-K=20
        3. MMR 重排序 → Top-5
        4. 按章节序号排序 → 返回
        """
        query_vec = self.embedder.embed(query)
        candidates = self.milvus.search(
            collection="scripts",
            vector=query_vec,
```

```python
class FunctionCallExecutor:
    """执行 AI 返回的 Function Call，写入 Redis"""

    async def execute(self, room_id: str, function_call: dict) -> dict:

                    f"room:{room_id}:player:{args['player_id']}",

                )
            case "add_item":

                    f"room:{room_id}:player:{args['player_id']}:items",
                    json.dumps({"name": args["item_name"], "qty": args["quantity"]})

            # ... 其他 cases
```

### 4.6 摘要记忆

```python
# services/summarizer.py
class MemorySummarizer:
    SUMMARY_TRIGGER_INTERVAL = 5  # 每 5 轮触发一次摘要

    async def maybe_summarize(self, room_id: str, round_num: int) -> str | None:
        """如果触发条件满足，生成新的摘要记忆"""
        if round_num % self.SUMMARY_TRIGGER_INTERVAL != 0:
            return None

        # 取前 N-10 轮的消息 + 旧的摘要记忆
        old_messages = await self._get_messages(room_id, before_round=round_num - 10)
        old_summary = await self.redis.get(f"room:{room_id}:summary")

        prompt = f"""将以下游戏日志压缩为一段简洁的摘要记忆，保留：
1. 剧情进展（关键事件、地点变更）
2. 角色状态变化（受伤、获得道具等）
3. 关键决策（玩家的重大选择）
4. NPC 关系变化

旧摘要：{old_summary or '无'}
新日志：{old_messages}

输出格式：一段 200-500 字的叙事摘要。"""

        new_summary = await self.llm.generate_sync(prompt)
        await self.redis.set(f"room:{room_id}:summary", new_summary)
        return new_summary
```

## 8. 安全设计

### 8.1 认证流程

```
┌────────┐                              ┌─────────┐
│ Client │                              │   Go    │
└───┬────┘                              └────┬────┘
    │                                        │
    │ POST /auth/login {account, password}   │
    │───────────────────────────────────────►│
    │                                        │ bcrypt.Compare(password, hash)
    │                                        │ 生成 Access Token  (15min)
    │                                        │ 生成 Refresh Token (7 days)
    │                                        │
    │◄── {token, refresh_token, expires} ────│
    │                                        │
    │ 后续请求: Authorization: Bearer <token> │
    │───────────────────────────────────────►│ 验证签名 + 过期时间
    │                                        │
    │ Token 过期 → POST /auth/refresh        │
    │ {refresh_token}                        │
    │───────────────────────────────────────►│ 校验 refresh_token
    │◄── 新 token 对 ────────────────────────│
```

- **Access Token**：JWT，有效期 15 分钟，含 `{user_id, username, iat, exp}`
- **Refresh Token**：随机 UUID，存入 Redis `refresh:{token} → user_id`，有效期 7 天
- **密码**：bcrypt cost=12
- **WebSocket 鉴权**：连接时 query string 传 Access Token，Hub 验证后绑定 user_id

### 8.2 安全措施

| 措施 | 实现 |
|------|------|
| SQL 注入 | GORM 参数化查询 |
| XSS | Vue 自动转义 + Content-Security-Policy 头 |
| CSRF | SPA + JWT Bearer，天然免疫 |
| 文件上传 | PDF MIME 白名单 + 魔数校验 + 大小限制 50MB |
| 接口限流 | Gin 中间件，令牌桶 60req/min per user |
| 敏感信息 | 密码 bcrypt，配置文件不入库，Redis 不暴露公网 |
| HTTPS | Nginx 终止 TLS，内网 HTTP 明文可接受 |
