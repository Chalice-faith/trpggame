## 1. 验收范围

本记录覆盖 M2.0 契约与实时通信基础，不包含好友、聊天、群组或多人房间业务：

- 公共 Origin 白名单、查询参数 JWT 鉴权和 WebSocket Upgrader。
- 游戏 `/ws` 与 IM `/ws/im` 两条独立实时通道。
- 游戏订阅、IM connected、双方 Ping/Pong 和严格错误信封。
- 同一通道内最新连接接管、旧连接拒绝和 Hub 幂等停止。
- 双通道并存、握手矩阵、异常关闭、慢连接、并发与日志安全回归。
- CI targeted race 配置及跨栈本地自动化检查。

## 3. 契约核对

| 契约 | 验收结果 |
|---|---|
| 游戏通道 | `/ws?token=<JWT>&room_id=<id>` 保持兼容；成功后发送 `subscribed`，沿用 1500—1508 错误码 |
| IM 通道 | `/ws/im?token=<JWT>`；成功后发送带 UUID `connection_id` 的 `connected`，沿用 1700—1705 错误码 |
| Origin 与 JWT | 两个通道复用公共握手组件；Origin 白名单与 JWT 查询参数校验优先级已由 Router 真实升级测试覆盖 |
| 单连接接管 | 同一通道内新连接接管旧连接；旧连接收到 `connection_replaced` 并以 4001 关闭 |
| 双通道隔离 | 同一用户可同时连接游戏与 IM；任一通道的接管不会替换另一通道连接 |
| 心跳 | 游戏与 IM 各自完成 Ping/Pong；IM 已覆盖延迟 Pong、缺失 Pong、正常关闭与 TCP 异常断开 |
| 生命周期 | 两个 Hub 的注册、投递、注销与 Stop 竞争均有回归；游戏旧连接不能误删新连接或继续提交入站消息 |
| 日志安全 | `/ws`、`/ws/im` 成功和失败请求均不在 Gin 访问日志中暴露查询参数 Token |
| REST/OpenAPI | D4 未修改公共 REST 路由或协议；OpenAPI lint 通过，无需更新接口契约 |

## 5. 已知非阻塞项

- Python 测试通过，但 AnyIO 测试路径仍会输出未关闭内存流的 `ResourceWarning`；该项沿用工程优化记录，不阻塞 M2.0。
- Vue 构建通过，但仍有 `@vueuse/core` 注解告警和主包超过 500 kB 的既有提示。
- Compose 配置解析通过，但顶层 `version` 字段会产生已废弃提示。
- 查询参数 Token 的应用日志回归已覆盖；部署时仍需确保反向代理和外部可观测平台不记录敏感查询串。
- M2.0 只提供 IM 连接基础，除 Ping 外的聊天业务消息、持久化与 Redis Pub/Sub 尚未实现。

## 6. 结论与下一步

M2.0-D 已完成本地验证、提交和 GitHub Actions 实际验证，M2.0 标记为“代码完成，等待部署验收”。在真实部署与端到端验证完成前，不能将 M2.0 标记为完整验收通过；是否恢复 Phase 1 部署验收或进入 M2.1，由开发者另行确认。
