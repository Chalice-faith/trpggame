## 3. 当前实时通信结构

| 通道 | 地址 | 作用 | 当前状态 |
|---|---|---|---|
| 游戏 | `/ws?token=<JWT>&room_id=<id>` | 房间订阅、行动流式叙事、状态事件与断线补推 | D1 已实现同房间同用户最新连接接管 |
| IM | `/ws/im?token=<JWT>` | 用户级社交通道 | M2.1 已接入好友关系事件、在线状态和 Vue 全局连接生命周期；M2.2-C 已接入 chat_message/chat_ack、conversation_updated 与 im_sync 业务帧 |

- 两个通道共享 `internal/realtime` 的查询参数 JWT 鉴权、Origin 白名单和 Upgrader 配置，但各自维护连接表，互不接管。
- IM 同用户新连接会收到新的 `connection_id`，旧连接收到 `connection_replaced` 后以应用关闭码 `4001` 关闭。
- IM 入站业务消息支持 `ping`、`chat_message` 与 `im_sync`；文本帧上限 32 KiB；服务端已推送 `presence`、`friendship_updated`、`chat_message`、`chat_ack`、`im_sync_batch` 与 `conversation_updated`，其他未支持入站类型返回 `1705 unsupported message type`。
- Gin 默认访问日志跳过 `/ws` 与 `/ws/im`，避免记录含 Token 的完整查询串；其他代理层仍需按部署指南关闭敏感查询日志。

## 4. 一致性与并发边界

- MySQL 是房间生命周期、玩家关系和存档的持久化权威；Redis 是实时运行态权威。
- Redis 行动提交通过请求 UUID、请求指纹、预期回合和运行态世代完成原子 CAS。
- 暂停从 `playing` 进入 `paused` 时原子轮换世代；恢复不会使旧世代重新有效。
- 读档先进入暂停隔离态，再原子替换 Redis 快照、清理旧行动缓存和自动存档待办，最后精确同步 MySQL 回合字段。
- 普通行动使用 MySQL `GREATEST` 单调推进进度，迟到请求不能覆盖更大的回合号。
- 自动存档先在 Redis 保存提交时的精确快照，再写入 MySQL；失败时同一请求可重试，且不会重复调用 AI。
- 结束游戏采用 Redis 与 MySQL 状态切换及补偿确认，并清理运行态。
- `trigger_event` 当前只随行动结果返回，尚未写入计划中的关键事件表。
