## 1. 目标与完成定义

M2.0 只建立 Phase 2 的稳定开发底座，不交付好友、聊天或多人房间业务页面。

完成时必须满足：

- Phase 2 数据表、状态机、业务索引和迁移归属完成评审。
- REST 路径、WebSocket 消息信封和错误码范围冻结。
- 新增 `/ws/im?token=<JWT>` 用户级实时通道。
- 同一用户在同一实时通道只保留最新连接，旧连接被明确关闭。
- IM 与游戏 WebSocket 可以在同一客户端同时连接，互不覆盖。
- 公共 WebSocket 共享 JWT 查询参数校验、Origin 校验和连接参数。
- Phase 1 游戏 WebSocket 协议和行为保持兼容，现有测试全部通过。
- Go 测试、静态检查、构建和 CI 全部通过。

## 3. 数据库设计冻结

M2.0 不新增 SQL 文件，只确认后续迁移归属。每个迁移随首次使用它的业务里程碑提交，避免空表长期存在。

| 迁移 | 所属里程碑 | 内容 | 核心约束 |
|---|---|---|---|
| `010_create_friendships.sql` | M2.1 | 好友申请与已接受关系 | 规范化双方 ID 唯一；状态机校验 |
| `011_create_conversations.sql` | M2.2 | 私聊/群聊统一会话 | 私聊双方唯一；群组会话唯一 |
| `012_create_conversation_members.sql` | M2.2 | 会话成员与读取水位 | 会话与用户组合唯一 |
| `013_create_messages.sql` | M2.2 | 持久化消息与会话 seq | 会话 seq 唯一；客户端请求幂等唯一 |
| `014_create_groups.sql` | M2.3 | 群组主表 | 群主和版本字段 |
| `015_create_group_members.sql` | M2.3 | 群成员与角色 | 群组与用户组合唯一 |
| `016_extend_game_rooms.sql` | M2.4 | 房间码、回合时限和版本 | 房间码唯一 |
| `017_extend_room_players.sql` | M2.4 | 成员状态和离开时间 | 房间角色占用唯一 |

统一规则：

- 不创建外键约束。
- 不创建外键专用索引。
- 只创建服务查询、唯一性、排序或幂等真正使用的业务索引。
- 关联存在性、删除清理与状态转换由 Service 事务保证。
- 每个 SQL 文件加入 `database/migrations/manifest.mjs`，并扩展迁移执行器测试。
- 已执行迁移不可原地修改；修正通过新迁移完成。

### 3.1 好友状态机

`pending → accepted | rejected`

- 双方同时申请时只保留一条规范化关系；已有反向 pending 申请时，第二次申请直接接受还是返回冲突，由 M2.1 实施方案单独确认。
- 删除好友不删除审计记录，状态转换为 `removed`；重新申请复用原关系并更新申请人和时间。

### 3.2 会话与消息状态

- 私聊会话只允许已接受好友创建。
- 群聊会话与群组一一对应。
- 会话 `last_seq` 在消息事务中原子递增。
- `messages` 使用 `(conversation_id, seq)` 保证顺序。
- `(conversation_id, sender_id, client_message_id)` 保证发送重试幂等。
- 消息持久化后才能实时推送；断线恢复以数据库 seq 为准。

### 3.3 多人房间状态

继续使用 `waiting → playing → paused ↔ playing → ended`，不增加第二套房间主表。

- 4—6 名真人玩家，AI GM 不占 `max_players`。
- `waiting` 状态允许加入、离开、选角和准备。
- 只有房主可开始、暂停、恢复、读档和结束。
- 开始后冻结 `turn_order`；成员异常离线不直接改变顺序。
- 游戏中的离开、踢人和房主转让规则在 M2.4 实施方案确认。

### 3.4 字段级契约

字段类型以 MySQL 8.4 为准，所有时间字段使用 `DATETIME(3)`，所有业务主键使用 `BIGINT UNSIGNED`。

#### `friendships`

| 字段 | 约束或用途 |
|---|---|
| `id` | 自增主键 |
| `user_low_id`、`user_high_id` | 规范化双方 ID，必须满足 low < high |
| `requested_by` | 最近一次申请发起人 |
| `status` | `pending`、`accepted`、`rejected`、`removed` |
| `created_at`、`updated_at` | 创建和最近状态变更时间 |
| `responded_at`、`removed_at` | 可空的响应和删除时间 |

业务索引：双方组合唯一；分别按 `(user_low_id, status, updated_at, id)` 和 `(user_high_id, status, updated_at, id)` 查询好友或申请。

#### `conversations`

| 字段 | 约束或用途 |
|---|---|
| `id` | 自增主键 |
| `type` | `direct` 或 `group` |
| `direct_low_id`、`direct_high_id` | 私聊双方规范化 ID，群聊时为空 |
| `group_id` | 群聊目标，私聊时为空 |
| `last_seq` | 当前已持久化消息水位，初始为 0 |
| `last_message_at` | 会话列表排序时间，可空 |
| `created_at`、`updated_at` | 创建和更新时间 |

业务索引：私聊双方组合唯一；`group_id` 唯一；按 `last_message_at` 的列表排序由成员表先定位会话后执行。

#### `conversation_members`

| 字段 | 约束或用途 |
|---|---|
| `id` | 自增主键 |
| `conversation_id`、`user_id` | 会话成员身份 |
| `role` | `member`、`admin`、`owner`；私聊固定为 `member` |
| `last_read_seq` | 客户端已读水位，不能超过会话 `last_seq` |
| `status` | `active` 或 `left` |
| `joined_at`、`left_at` | 加入和离开时间 |

业务索引：会话与用户组合唯一，该唯一索引同时支持按会话查成员；另按 `(user_id, status, conversation_id)` 查询用户会话。

#### `messages`

| 字段 | 约束或用途 |
|---|---|
| `id` | 自增主键 |
| `conversation_id`、`seq` | 会话及其单调消息序号 |
| `sender_id` | 发送人 ID，系统消息使用 0 |
| `client_message_id` | 客户端 UUID；系统消息由服务端生成 |
| `message_type` | 首版允许 `text`、`system` |
| `content` | 文本正文，首版最大 4000 个 Unicode 字符 |
| `metadata` | JSON 扩展数据，默认空对象 |
| `created_at` | 服务端持久化时间 |

业务索引：`(conversation_id, seq)` 唯一；`(conversation_id, sender_id, client_message_id)` 唯一；历史消息按 `(conversation_id, seq)` 游标读取，不额外建立时间索引。

#### `groups` 与 `group_members`

- `groups`：`id`、`name`、`avatar_url`、`owner_id`、`version`、`created_at`、`updated_at`、`deleted_at`。
- `group_members`：`id`、`group_id`、`user_id`、`role`、`status`、`joined_at`、`left_at`。
- 群名称首版为 1—128 个字符；角色允许 `member`、`admin`、`owner`。
- 业务索引：群成员组合唯一；按用户列出有效群组；按群组列出有效成员；按 owner 查询群组。

#### 多人房间扩展

- `game_rooms` 新增 `join_code CHAR(10)`、`turn_timeout_seconds INT UNSIGNED`、`version BIGINT UNSIGNED`。
- 房间码使用不易混淆的大写字母和数字，数据库唯一；结束后不复用。
- 回合时限允许 30—600 秒，默认 120 秒。
- `room_players` 新增 `member_status`、`left_at`；状态允许 `joined`、`left`、`kicked`。
- 同一房间同一预设角色只允许一个有效玩家占用；离开或被踢时事务内清空 `character_id` 和准备状态。
- 业务索引：房间码唯一；房主房间列表；房间成员与行动顺序；有效角色占用唯一。

## 4. REST 与错误码冻结

M2.0 不新增业务 REST Handler，但冻结模块范围，后续必须同步维护 OpenAPI：

| 错误码范围 | 模块 |
|---|---|
| `1600—1699` | 用户搜索与好友关系 |
| `1700—1799` | 会话、消息与 IM WebSocket |
| `1800—1899` | 群组与群成员 |
| `1900—1999` | 多人房间与回合 |

统一约束：

- REST 继续使用 `{"code":0,"message":"ok","data":...}`。
- 资源 ID 使用十进制正整数；非法 ID 返回模块内参数错误码。
- 列表接口使用游标或稳定排序分页，不使用会漂移的消息 offset 分页。
- 新公共路由必须同时加入 OpenAPI，现有路由契约测试继续作为 CI 门禁。
- Handler 只映射 HTTP 与安全错误文案，权限和状态判断放在 Service。

## 5. WebSocket 协议冻结

### 5.1 入口与身份

| 通道 | 地址 | 身份范围 | 活动连接规则 |
|---|---|---|---|
| 游戏 | `/ws?token=<JWT>&room_id=<id>` | 用户 + 单个游戏房间 | 同一房间同一用户保留最新连接 |
| IM | `/ws/im?token=<JWT>` | 用户全局社交通道 | 同一用户保留最新连接 |

- 两个通道分别管理连接，因此同一用户可以同时拥有一条 IM 连接和一条游戏连接。
- 相同通道的新连接注册成功后，服务端以应用关闭码 `4001` 和原因 `connection_replaced` 关闭旧连接。
- 旧连接后续触发 unregister 时必须校验连接 ID，不能删除新连接。
- Access Token 缺失返回 HTTP `401 / 1700`，无效或过期返回 `401 / 1701`。
- Token 继续通过查询参数传递以兼容浏览器 WebSocket；日志不得记录完整查询串或 Token。

### 5.2 IM 客户端消息信封

```json
{
  "type": "ping",
  "request_id": "可选 UUID",
  "data": {}
}
```

字段规则：

- `type` 必填，最大 64 字符，仅允许已注册类型。
- `request_id` 供业务请求幂等与关联，Ping 可省略。
- `data` 是消息类型专属 JSON 对象，最大消息体沿用 8 KiB 限制。
- 客户端不能提交 `user_id`、服务端时间或持久化 seq。

M2.0 只接受 `ping`，其他类型返回 `error / 1705 / unsupported message type`。

### 5.3 IM 服务端消息信封

```json
{
  "type": "connected",
  "request_id": "可选 UUID",
  "timestamp": 1788796800000,
  "data": {
    "user_id": 7,
    "connection_id": "UUID"
  }
}
```

M2.0 服务端消息类型：

| 类型 | 用途 |
|---|---|
| `connected` | 新连接接管完成，返回用户和连接 ID |
| `pong` | 应用层 Ping 响应 |
| `error` | 协议、解析或未支持消息错误 |
| `connection_replaced` | 在关闭旧连接前告知被新连接接管 |

后续预留但本里程碑不处理：`chat_message`、`chat_ack`、`im_sync`、`im_sync_batch`、`presence`、`conversation_updated`。

### 5.4 Origin 安全

游戏与 IM WebSocket 已分别在 M2.0-B、M2.0-C 接入统一 Origin 配置：

- 新配置：`TRPG_WEBSOCKET_ALLOWEDORIGINS`，逗号分隔完整 Origin。
- 开发默认：`http://localhost:5173,http://127.0.0.1:5173`。
- 非浏览器客户端缺少 Origin 时允许连接，身份仍由 JWT 校验。
- 浏览器 Origin 不在白名单时返回升级失败，不泄露内部信息。
- 不支持通配符与带路径 Origin，配置启动时完成标准化和校验。

### 6.1 Router 注入方式

将当前单个 `wsHandler gin.HandlerFunc` 参数替换为结构体，避免继续增加位置参数：

```go
type WebSocketHandlers struct {
    Game gin.HandlerFunc
    IM   gin.HandlerFunc
}
```

`router.Setup` 只负责非空 Handler 的路径注册，不在 Router 内创建 Hub 或业务依赖。所有现有 Router 测试同步改用结构体。

### 6.2 Hub 接管规则

IM Hub 只允许自己的事件循环修改连接表：

1. 新 Client 生成不可复用的 `connection_id`。
2. register 收到同一 user ID 时，先登记新 Client，再通知并关闭旧 Client。
3. unregister 同时比较 user ID 和 connection ID，仅匹配当前连接时才删除。
4. Hub Stop 只执行一次，关闭全部 Client 并等待事件循环退出。
5. Client Send 缓冲区满时关闭该连接；IM 消息未来可由数据库补推，不静默维持失步连接。

## 8. 测试清单

### 8.1 配置与安全

- 默认 Origin 只包含两个本地前端地址。
- 空项、带路径、非法 URL 和通配符配置被拒绝。
- 白名单 Origin 可升级，其他浏览器 Origin 被拒绝。
- 无 Origin 的非浏览器客户端可升级。
- 缺失、无效和过期 JWT 在升级前拒绝。
- 日志与错误响应不包含 Token。

### 8.2 IM Hub

- 首次注册收到 `connected`。
- 同用户第二条连接注册后，第一条收到 `connection_replaced` 并关闭。
- 旧连接 unregister 不删除新连接。
- 不同用户连接互不覆盖。
- IM 连接与同用户游戏连接可以同时存在。
- 并发 register/unregister 不发生 panic、重复 close 或数据竞争。
- Hub Stop 可安全关闭当前连接且不会泄漏 goroutine。

### 8.3 协议与 Client

- Ping 返回 Pong，服务端控制帧心跳正常延长读截止时间。
- 非法 JSON、空 type、未知 type 和超限消息返回稳定错误或关闭连接。
- 客户端伪造 user ID、timestamp、seq 不会进入服务端消息。
- Send 缓冲区满时连接被关闭，未来可通过持久化 seq 恢复。

### 8.4 回归

- 现有游戏 WS 鉴权、订阅、seq、sync 和行动分发测试全部通过。
- Go 全量测试、`go vet ./...`、`go build ./cmd/server` 通过。
- `go test -race ./...` 在支持 CGO 的环境通过。
- OpenAPI、数据库迁移、Python、Vue 与 Compose CI 不回退。

## 10. M2.1 预留接口

M2.0 的 IM Hub 仅预留以下依赖注入点，不提供空数据库实现：

- `PresenceObserver`：连接接管、上线和离线通知，M2.1 接 Redis presence。
