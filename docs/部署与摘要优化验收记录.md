首次部分集成测试与临时运行的 Go 归档/摘要 worker 共用测试数据库，产生竞争失败；停止临时服务后重跑通过。存档错误优先级冲突和分支摘要版本继承问题已修正，没有放宽既有门禁断言。

Windows 没有配置 cgo race 编译器，因此 race 在 Linux 容器执行。默认 `node:24-alpine` 下载遇到外部网络超时；实际 Dockerfile 通过 `NODE_IMAGE` 参数使用已缓存的 Node 20.20.2 构建基底完成验证。默认 Node 24 全新镜像拉取和整套生产镜像冷构建不列为已通过。前端仍有既有 chunk/注解告警，Python 测试仍有依赖 ResourceWarning；均未导致测试失败。

## 真实对象与向量链路

1. 注册隔离账号，通过 Go 上传正常 PDF；MinIO 业务用户可读取对应对象。
2. Python 真实读取 PDF、解析/切片、加载 BGE、编码1024维并写入 Milvus；Go 状态回调变为 ready。
3. 本次正常样本产生3片段，实际 Milvus 查询数量为3；摘要接口未带共享密钥返回401。`/ready` 的存储依赖为 ready，AI 为 missing_key、HTTP503，符合无密钥状态。
4. 通过 Go 删除剧本，实际对象及向量均消失，业务详情返回404。
5. 上传真实空白 PDF，解析器失败并回调 failed。只修复本次测试对象内容，再调用公开 retry 接口，真实解析重新得到3片段；最后删除并确认向量清理。
6. 在同一隔离 MinIO 实际执行发布初始化脚本。剧本用户读/写/删自身桶成功，写 Milvus 桶及无关桶被 AccessDenied 拒绝；Milvus 用户读写自己的桶成功。

重复执行示例（先启动隔离依赖及 Go/Python，按部署指南设置匹配的 env，不把密钥写入命令历史）：

```bash
python scripts/generate-m13-fixtures.py --verify
python scripts/verify-storage-chain.py --go-url http://127.0.0.1:38080 --ai-url http://127.0.0.1:38000
```

使用 Python AI 的虚拟环境；脚本需要 `TRPG_AI_MINIO_*`、`TRPG_AI_MILVUS_HOST/PORT/COLLECTION_NAME` 指向同一隔离实例，只应在可丢弃验收环境执行。

验收结束后已停止本次临时 Go/Python、静态 Nginx 及 `trpg_opt_1009` 栈，保留隔离数据卷、模型缓存和脱敏证据。用户原有容器未停止。
