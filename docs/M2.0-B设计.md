## 1. 目标

M2.0-B 把 M2.0-A 已验证的 Origin 白名单和查询参数 JWT 鉴权接入现有游戏 WebSocket `/ws`，消除当前无条件放行 Origin 和重复鉴权逻辑。

本块完成后：

- 服务启动时校验 WebSocket Origin 配置，配置非法则立即退出。
- 游戏 WebSocket 按统一顺序执行 Origin、Token、房间参数和房间权限校验。
- Gorilla WebSocket Upgrader 使用同一 OriginSet 作为第二层校验。
- `/ws` 路径、成功消息、房间订阅、seq、sync 和原有错误码保持兼容。
- 为后续 M2.0-C 的 `/ws/im` 提供可复用 Upgrader。

## 2. 实施边界

### 2.1 本块实现

- 新增公共 WebSocket Upgrader 工厂。
- 在 main 启动早期解析 `TRPG_WEBSOCKET_ALLOWEDORIGINS`。
- 游戏 WebSocket 改用 `realtime.AuthenticateQueryToken`。
- 游戏 WebSocket 启用 Origin 白名单，并新增错误码 `1508`。
- 增加公共组件和游戏握手测试。
- 更新已生效的 Origin 配置说明。

### 2.2 本块不实现

- 不注册 `/ws/im`。
- 不实现 IM Hub、Client 或连接接管。
- 不改游戏 Hub、Client、消息信封、seq、sync 或行动处理。
- 不调整 Router.Setup 的参数结构。
- 不新增数据库迁移、Redis Pub/Sub 或业务表。
- 不改变“同账号多设备不支持”的既定产品决策；该行为由 M2.0-C 分通道实现。

## 3. 接线结构

```text
config.Load
  -> realtime.ParseAllowedOrigins
  -> ws.HandleWebSocket(hub, jwtSecret, originSet, roomAuthorizer)
       -> Origin 预检
       -> realtime.AuthenticateQueryToken
       -> room_id 校验
       -> RoomAuthorizer
       -> realtime.NewUpgrader(originSet).Upgrade
       -> 现有 Hub / Client
```

M2.0-B 只替换握手入口，升级成功后的数据流不变。

## 5. 公共 Upgrader

新增：

```go
func NewUpgrader(origins *OriginSet) websocket.Upgrader
```

固定配置：

```go
websocket.Upgrader{
    ReadBufferSize:  4096,
    WriteBufferSize: 4096,
    CheckOrigin:     origins.Allows,
}
```

约束：

1. 每个 Handler 工厂只创建一次 Upgrader，不在每次请求中重复创建。
2. Upgrader 只保存只读 OriginSet，允许并发升级。
3. nil OriginSet 不得降级为全部放行；其 CheckOrigin 必须返回 false。
4. M2.0-C 的 IM Handler 复用同一工厂，不复制缓冲区或 Origin 规则。

Handler 在调用 Upgrade 前仍显式执行 Origin 预检。预检用于返回稳定 JSON 错误，Upgrader 的 CheckOrigin 用于防止后续维护时绕过预检。

## 6. 游戏 Handler 调整

计划签名：

```go
func HandleWebSocket(
    hub *Hub,
    secret string,
    origins *realtime.OriginSet,
    authz RoomAuthorizer,
) gin.HandlerFunc
```

Handler 工厂内部执行：

```go
upgrader := realtime.NewUpgrader(origins)
```

请求校验必须保持以下顺序：

1. Origin 是否允许。
2. 查询参数 Token 是否存在且有效。
3. `room_id` 是否为当前平台可表示的正整数。
4. 当前用户是否有房间订阅权限。
5. 执行 WebSocket Upgrade。
6. 创建现有游戏 Client 并注册到 Hub。

Origin 放在最前，原因是浏览器来源不可信时不应通过响应差异探测 Token 或房间状态。因此，不允许的 Origin 即使同时缺 Token，也固定返回 `1508`。

## 7. 错误契约

在 `internal/ws/handler.go` 中为握手错误建立具名常量，避免继续散落魔法数字。

| 校验失败 | HTTP | 业务码 | message |
|---|---:|---:|---|
| Origin 不允许 | 403 | 1508 | `origin not allowed` |
| 缺少 Token | 401 | 1500 | `missing token` |
| Token 无效 | 401 | 1501 | `invalid token` |
| `room_id` 非法 | 400 | 1502 | `invalid room_id` |
| 无房间权限或权限查询失败 | 403 | 1503 | `room access denied` |

兼容要求：

- `1500—1503` 的 HTTP 状态、业务码和 message 不变。
- `1504—1507` 属于升级后的游戏消息处理，不作修改。
- Origin 预检失败返回 Gin JSON；Upgrader 二次校验失败只记安全日志，不再尝试写第二份响应。
- 日志不得包含完整 Token。

## 8. 启动配置

`cmd/server/main.go` 在 `config.Load()` 成功后、初始化数据库及外部依赖前执行：

```go
allowedOrigins, err := realtime.ParseAllowedOrigins(
    cfg.WebSocket.AllowedOrigins,
)
if err != nil {
    log.Fatalf("Invalid WebSocket allowed origins: %v", err)
}
```

这样可以在尚未建立 MySQL、Redis、MinIO 等连接前发现部署配置错误，避免服务部分初始化后才失败。

默认配置继续支持当前本地前端。正式部署前必须把浏览器实际页面的完整 Origin 写入环境变量，例如：

```env
TRPG_WEBSOCKET_ALLOWEDORIGINS=https://trpg.example.com
```

协议、主机和非默认端口都参与精确匹配；配置值不包含页面路径。

## 9. 测试设计

### 9.1 公共 Upgrader 单元测试

- 读写缓冲区均为 4096。
- 允许白名单内 Origin。
- 拒绝白名单外、`null`、多值和非法 Origin。
- 缺少 Origin 时允许非浏览器客户端继续后续鉴权。
- nil OriginSet 不允许升级。

### 9.2 游戏握手真实升级测试

扩展现有 `httptest.Server + websocket.Dialer` 测试辅助函数，使其可传入 Origin Header，并读取失败响应 JSON。

覆盖：

- 允许 Origin + 合法 Token + 合法房间：成功升级并收到 `subscribed`。
- 无 Origin + 合法 Token：成功升级，保证原生客户端兼容。
- 不允许 Origin：HTTP 403，JSON 为 `1508`。
- `Origin: null`：HTTP 403，JSON 为 `1508`。
- 多值 Origin：HTTP 403，JSON 为 `1508`。
- 不允许 Origin + 缺 Token：仍返回 `1508`，验证校验优先级。
- 允许 Origin + 缺 Token：保持 `1500`。
- 允许 Origin + 无效 Token：保持 `1501`。
- 允许 Origin + 非法房间：保持 `1502`。
- 允许 Origin + 无房间权限：保持 `1503`。
- 现有订阅、广播和 sync 测试继续通过。

### 9.3 启动接线验证

- 代码级测试覆盖配置解析器；main 只负责调用与注入。
- 构建 server，确保依赖注入签名完整。
- 文档和环境变量名称与 Viper 映射保持一致。

## 12. 风险与回滚

### 12.1 风险

- 部署环境未配置实际前端 Origin 时，浏览器游戏连接会收到 `1508`。
- 反向代理改写 Host 不影响 Origin Header，但错误的协议或端口配置仍会被精确拒绝。
- 非浏览器客户端无 Origin 仍被允许，因此 Origin 不能替代 JWT 和房间权限。
- 校验顺序变化会让“不允许 Origin + 其他错误”优先返回 `1508`，这是明确的安全契约变化。

### 12.2 回滚

若接线导致回归，只回滚 M2.0-B 提交即可恢复旧游戏握手；M2.0-A 的配置、鉴权函数和 IM 消息契约可独立保留。禁止通过恢复 `CheckOrigin: return true` 作为长期修复，部署配置问题应修正白名单。
