## 1. 产品概述

### 1.1 产品定位

一款基于多人在线聊天平台的 **AI 驱动 TRPG 主持人**，支持玩家通过文本聊天的方式，随时随地进行单人或多人的桌面角色扮演游戏。AI 承担传统人类 GM（Game Master）的职责——包括叙事推进、NPC 扮演、规则裁定——让玩家无需寻找专业主持人即可获得高质量的跑团体验。

### 1.2 核心价值

| 痛点 | 解决方案 |
|------|----------|
| 找 GM 难，专业主持人稀缺 | AI 代理 GM，7×24 小时可用 |
| 跑团门槛高（规则复杂、准备耗时） | 导入 PDF 剧本即可开始，AI 自动理解剧情 |
| 线下凑人难、时间协调成本高 | 在线异步/同步结合，随时开团 |
| 长剧本 AI 记忆衰退、幻觉严重 | RAG + MMR + 摘要记忆，稳定 100+ 轮 |

### 1.3 产品形态 ✅

- **前端**：Web 单页应用（WebSocket 长连接）✅ *已确认：Vue 框架，仅 Web 端，不含小程序*
- **后端**：Go 服务（IM、用户、房间、剧本管理）+ Python 服务（AI 推理、RAG、Function Calling）
- **数据库**：MySQL（持久化）+ Redis（缓存 / 会话状态 / 消息队列）

### 4.2 技术选型

| 层次 | 技术 | 选型理由 |
|------|------|----------|
| 后端框架 | Go (Gin/Echo) + WebSocket (gorilla/websocket) | 高并发、低延迟、天然适合 IM 场景 |
| AI 服务 | Python (FastAPI) | 生态丰富，LLM SDK、向量库、PDF 解析库齐全 |
| AI 模型 | GLM-4-Long (1M 上下文) ✅ | 已确认，成本低、上下文长、适合长剧本场景 |
| ORM | GORM (Go) / SQLAlchemy (Python) | |
| 数据库 | MySQL | 成熟的关系型数据库，支持 JSON 字段 |
| 缓存 | Redis | 会话状态、Function Calling 缓存 |
| 向量数据库 | Milvus ✅ | 已确认，功能全、性能强 |
| 对象存储 | MinIO 自部署 ✅ | PDF 文件存储 |
| 消息队列 | 无（MVP 阶段） ✅ | Go ↔ Python 通过 HTTP/gRPC 同步调用 |
| 容器化 | Docker + Docker Compose ✅ | 开发/测试环境 |

### 4.3 Go ↔ Python 服务通信 ✅

- **同步调用**：Go 通过 HTTP/gRPC 调用 Python AI 服务的推理接口（MVP 阶段不引入消息队列）
- **流式输出**：AI 推理结果通过 WebSocket 流式推送给前端
- *已确认：AI 推理耗时较长（5-30s），前端通过 WebSocket 接收流式输出*

## 5. AI 服务设计

### 5.1 核心 AI 流程

```
玩家输入行动
      │
      ▼
┌─────────────────┐
│ 1. 上下文组装     │
│  - 系统提示词    │
│  - 摘要记忆      │
│  - 最近10轮对话   │
│  - RAG检索片段    │ ← 向量检索 + MMR 去重
│  - 角色当前状态   │ ← 从 Redis 读取
└───────┬─────────┘
        ▼
┌─────────────────┐
│ 2. LLM 推理      │
│  - GLM-4-Long    │
│  - 叙事生成      │
│  - 规则裁定      │
│  - FunctionCall  │ → 需要状态变更时调用
└───────┬─────────┘
        ▼
┌─────────────────┐
│ 3. 后处理        │
│  - 执行FC写Redis │
│  - 更新摘要记忆  │
│  - 返回叙事文本  │
└───────┬─────────┘
        ▼
     广播给玩家
```

### 5.2 RAG 剧本检索流程 ✅

```
PDF 上传
  │
  ▼
PDF 解析 (PyMuPDF / pdfplumber)
  │
  ▼
文本清洗（去页眉页脚、分页符、空行压缩）
  │
  ▼
按章节结构化切片（基于标题/分隔符模式识别）
  │
  ▼
提取元数据 {章节号, 标题, 角色列表, 场景描述, 位置}
  │
  ▼
Embedding 向量化 + 存入向量数据库
  │
  ▼
────────── 运行时检索 ──────────
  │
  ▼
当前上下文构建查询向量
  │
  ▼
向量相似度检索（Top-K = 20）
  │
  ▼
MMR 算法重排序（λ=0.7, 最终返回 Top-5）
  │
  ▼
按章节序号排序（保证章节顺序逻辑）
  │
  ▼
注入 LLM 上下文
```

**MMR 参数**：平衡相关性（λ）和多样性（1-λ），推荐 λ=0.7，在叙事场景下适度偏向多样性避免同质化。

### 5.3 Function Calling 设计 ✅

AI 可调用的函数：

| 函数名 | 参数 | 描述 |
|--------|------|------|
| `update_player_status` | `{player_id, field, value}` | 更新角色 HP/MP/SAN 等数值 |
| `add_item` | `{player_id, item_name, quantity, description}` | 角色获得道具 |
| `remove_item` | `{player_id, item_name, quantity}` | 角色失去道具 |
| `add_buff` | `{player_id, buff_name, duration}` | 角色获得 BUFF/DEBUFF |
| `set_location` | `{player_id, location}` | 更新角色当前位置 |
| `trigger_event` | `{event_name, description}` | 记录关键剧情事件 |
| `roll_dice` | `{dice_type, target, reason}` | 触发骰子检定（服务端真随机） |

### 5.4 摘要式记忆策略 ✅

```
┌─────────────────────────────────────────┐
│ 游戏轮次: N                              │
│                                          │
│ [摘要记忆] ← 前 N-10 轮的压缩叙事        │
│   每次生成摘要后替换旧摘要                │
│                                          │

```

 │    ├── max_players, current_turn, turn_order[]
 │    └── RoomPlayer (房间玩家)
 │         ├── room_id, user_id, character_id, player_order
 │
 ├── Script (剧本)
 │    ├── id, title, description, file_path, user_id
 │    ├── chunk_count, status(uploading/parsing/ready/failed)
 │    ├── parse_error, deleted_at
 │    └── ScriptCharacter (预设角色)
 │         ├── script_id, name, attributes(JSON), background
 │
 ├── GameSave (游戏存档)
 │    ├── id, room_id, round_number, created_at
 │    ├── summary_memory, redis_snapshot(JSON)
 │    └── recent_messages[] (最近10轮完整记录)
 │
 └── PlayerState (运行时状态 — Redis)
      ├── user_id, room_id
      ├── hp, mp, san, location
      ├── items[], buffs[], status[]
      └── last_updated

## 8. MVP 分期规划 ✅ *已确认 Phase 1 → 2 → 3*

### Phase 1 — MVP（单人 AI 跑团闭环）

**目标**：1 个玩家 + AI 主持人，完成一个完整剧本。

| 模块 | 内容 |
|------|------|
| 用户系统 | 注册、登录、个人信息 |
| 剧本管理 | PDF 上传、解析、结构化、向量化存储 |
| AI 核心 | GLM-4-Long 推理、RAG 检索（含 MMR）、Function Calling、摘要记忆 |
| 游戏 | 单人快速开始、自由文本交互、骰子检定、存档读档 |
| 前端 | 单人跑团聊天界面（极简版） |

**不含**：好友系统、IM 系统、多人房间、群聊

| 模块 | 内容 |
|------|------|

| IM 系统 | WebSocket、私聊、群聊、AI 拉群、心跳重连 |
| 多人跑团 | 回合制、角色选择、广播叙事 |
| 前端 | 完整的 IM 面板 + 跑团界面 |

### Phase 3 — 体验增强

| 模块 | 内容 |
|------|------|
| 记忆增强 | 关键事件标记、语义记忆检索 |

| 多端 | 移动端适配 / 小程序 |
