## 1. 目标

M2.0-D 是实时通信基础里程碑的收尾块，不新增好友或聊天业务。它负责消除重复连接和停止流程中的并发缺口，补齐真实 WebSocket 异常路径测试，把 race 检测接入 CI，并形成可审计的 M2.0 验收记录。

完成后：

- 游戏和 IM 通道都遵循“同一通道最新连接生效”的首版规则。
- 旧连接无法删除新连接，也不能在被接管后继续提交游戏行动。
- IM Hub 在并发注册、注销、投递和停止下不死锁、不 panic。
- 异常帧、超限、慢连接、服务停止和重复连接均有自动化证据。
- Linux CI 执行受影响实时通信包的 race 检测。
- M2.0 的本地验证、CI 验证和未执行的真实部署验证被明确区分。

- 让游戏 Hub 的注册、注销、投递和 Stop 在停止期间安全返回。

## 3. 规划冲突与处理决定

早期《Phase 2 规划设计》把游戏通道显式接管安排在 M2.4；后续更具体的《M2.0 实施方案》又要求同一实时通道的新连接关闭旧连接。

当前游戏 Hub 的实际行为是：

1. 同一房间同一用户注册新 Client 时，map 直接覆盖为新 Client。
2. 旧 WebSocket 没有被关闭，仍可从 readPump 调用 HandleInbound。
3. 旧连接稍后 unregister 时只按 user ID 删除，会误删新 Client。

这不是多人房间业务，而是已有连接层的正确性和安全问题。M2.0-D 按较新的具体契约处理：

- 本块完成游戏通道的连接接管、当前连接校验和安全注销。
- M2.4 只负责多人房间成员鉴权、房间状态与多人行动，不再重复实现底层接管。
- 游戏成功订阅消息、业务事件和错误码保持不变；只改变同一用户重复连接时的行为。

## 5. 共享关闭契约

在 internal/realtime/websocket.go 定义：

    const CloseCodeConnectionReplaced = 4001
    const CloseReasonConnectionReplaced = "connection_replaced"
    const CloseReasonServiceUnavailable = "service unavailable"

游戏与 IM 包引用同一常量，避免两个通道对相同产品语义使用不同数值或拼写。

兼容处理：

- imws 已公开的同名常量可保留为 realtime 常量的别名，避免内部调用点无意义变化。
- 游戏通道接管只发送 Close 帧，不新增游戏业务消息类型，不占用房间 seq。
- IM 通道继续先发送 connection_replaced 文本消息，再发送 4001 Close 帧。

## 6. 游戏 Hub 并发修复

### 6.1 Client 身份

游戏 Client 增加内部 ConnectionID，由 NewClient 生成 UUID v4。该字段不加入游戏消息 JSON，也不改变客户端协议。

唯一连接键仍为 room_id + user_id；ConnectionID 只用于区分同一键的不同物理连接。

### 6.2 注册确认

把直接写入 hub.register 改为安全公开方法：

    func (h *Hub) Register(client *Client) bool
    func (h *Hub) Unregister(client *Client)

Register 等待 Hub 事件循环确认：

- Hub 正常且 Client 有效：返回 true。
- Hub 已停止或正在退出：返回 false。
- 注册失败时 Handler 在已升级连接上发送 1013 / service unavailable 并关闭。

这样避免 Upgrade 成功后注册请求留在已停止 Hub 的缓冲 channel 中。

### 6.3 重复连接接管

同一房间、同一用户注册新连接：

1. 保存旧 Client。
2. 把 room map 更新为新 Client。
3. 向新 Client 排队原有 subscribed，seq 使用当前房间水位。
4. 向旧 Client 下发 4001 / connection_replaced 关闭命令。
5. Register 返回成功。

旧 Client 的 writePump 独占 Close 帧写入，避免与业务消息和 Ping 并发写 WebSocket。

### 6.4 当前连接校验

以下入口在处理前都必须确认 room map 中的 Client 指针和 ConnectionID 与调用者一致：

- unregister；
- HandleInbound；
- sync；
- 游戏行动；
- 针对指定 Client 的错误响应。

旧连接被替换后不能再提交 game_action、不能请求 sync、不能收到新响应，延迟 unregister 也不能删除新连接。房间广播和 SendToUser 始终使用 map 中的新 Client。

### 6.5 Stop

游戏 Hub 增加 stopOnce 与 done：

- Stop 可被重复或并发调用。
- 第一次 Stop 关闭信号并等待 Run 退出。
- Run 关闭当前连接、清空房间后关闭 done。
- Register、Unregister、Broadcast 和 Send 在 done 后立即返回。

生产调用顺序仍是先启动 Run，再暴露 Handler；不支持未启动 Run 就同步调用 Stop。

## 7. IM Hub 并发与生命周期验证

M2.0-C 已实现事件循环、注册确认和幂等 Stop。D 阶段以测试为主，只有测试暴露问题时才做最小修复。

重点不变量：

1. clients 只由 Hub.Run 修改。
2. Register/Send 等待的 result channel 有容量，Hub 不因调用方取消等待而阻塞。
3. Stop 关闭 done 后，所有等待中的公开方法都能返回。
4. 同用户最终 map 只指向最后一个成功注册的 Client。
5. 旧连接 close/unregister 不影响当前连接。
6. Client send channel 不被并发关闭，不出现 send-on-closed。
7. 慢连接移除后不会继续接收投递。

并发压力场景：

- 32—64 个用户并发注册、投递、注销，循环至少 100 次。
- 同一用户连续接管 50 次，最终连接仍能 Ping/Pong。
- Register、SendToUser、Unregister 与 Stop 并发执行。
- Stop 并发调用 20 次，所有调用在超时前返回。
- 旧连接关闭事件乱序到达，最新连接始终保留。

测试不能直接在 Hub 运行期间无锁读取 map；应通过有确认的公开方法或仅在 Stop 完成后检查内部状态。

## 8. Client 心跳与异常关闭

### 8.1 可测试时序

生产参数保持：

- write wait：10 秒；
- pong wait：60 秒；
- ping period：54 秒；
- max text：8192 字节；
- send buffer：256。

为避免测试等待一分钟，将 Client 构造拆为默认生产配置与包内测试配置：

    type clientOptions struct {
        writeWait      time.Duration
        pongWait       time.Duration
        pingPeriod     time.Duration
        maxMessageSize int64
        sendBufferSize int
    }

NewClient 永远使用生产默认值；测试通过未导出的构造器传入毫秒级时序。禁止使用会被并发测试修改的包级可变变量。

### 8.2 异常矩阵

- 客户端正常 Close：服务端读写协程退出并注销。
- 客户端直接断开 TCP：当前连接最终移除。
- 服务端 Hub Stop：所有连接关闭，公开调用返回。
- 不回复控制帧 Pong：超过测试 pongWait 后关闭。
- 正常 Pong：读取期限延长，连接继续可 Ping。
- 二进制帧：1003。
- 超过 8 KiB：1009。
- Upgrade 后 Hub 已停止：1013。
- 同用户重复连接：旧连接 4001，新连接继续可用。
- send buffer 满：慢连接关闭，后续投递返回 false。

每个测试设置明确的秒级总超时，失败时不能永久挂住 CI。

## 9. 双通道隔离测试

使用同一用户 Token 同时连接游戏 /ws 和 IM /ws/im：

- 游戏连接首条消息仍为 subscribed。
- IM 首条消息为 connected。
- IM 重连只替换旧 IM 连接，不关闭游戏连接。
- 游戏同房间重连只替换旧游戏连接，不关闭 IM 连接。
- 两个通道 Ping/Pong 各自使用原协议。

游戏测试继续使用 fake RoomAuthorizer，不连接数据库。

## 10. 握手与安全回归

## 15. 风险与控制

- **游戏行为变化**：仅影响同房间同用户重复连接，首次连接和正常重连协议不变。
- **旧连接仍提交行动**：Hub 在 HandleInbound 最前验证当前 Client。
- **旧注销误删新连接**：同时比较 room、user、ConnectionID 和指针。
- **并发写 Close 帧**：Close 命令由各自 writePump 执行。
- **Stop 死锁**：公开方法监听 done，测试覆盖 Register、Send 与 Stop 竞争。
- **测试假阳性**：压力测试通过公开确认接口同步，不用 sleep 判断状态。
- **测试过慢**：生产超时常量不变，测试使用独立 options。
- **CI 未实际运行**：本地只能验证 workflow 内容，验收记录保留 GitHub Actions 待确认状态。
- **范围扩张**：不加入聊天、数据库、Redis 或多人房间权限。
