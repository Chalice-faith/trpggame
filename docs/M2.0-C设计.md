## 1. 目标

M2.0-C 建立独立于游戏通道的用户级 IM WebSocket 连接基础，注册 `/ws/im?token=<JWT>`，交付单活动连接接管、基础 Ping/Pong、稳定错误响应和可停止的 Hub 生命周期。

本块完成后：

- 同一用户在 IM 通道只保留最新连接。
- 新连接接管旧连接时，旧连接收到 `connection_replaced`，随后以应用关闭码 `4001` 关闭。
- 同一用户仍可同时保留一条游戏连接和一条 IM 连接。
- IM 通道复用公共 Origin 与查询参数 JWT 鉴权。
- IM 通道只处理基础 Ping，业务聊天消息仍明确拒绝。
- main 可以独立启动和停止游戏 Hub 与 IM Hub。

- 不实现好友、私聊、群聊、presence 或离线消息。

## 3. 双通道结构

```text
                     +-> game Hub -> room_id + user_id -> /ws
JWT + Origin + Router
                     +-> IM Hub   -> user_id           -> /ws/im
```

两个 Hub 是独立实例和独立连接表：

- 游戏通道继续按房间与用户管理连接，不受 IM 连接表影响。
- IM 通道的替换只影响该用户原有 IM 连接。
- IM Hub 不引用游戏 Hub，也不通过共享 map 实现“全局单连接”。

## 5. IM Hub

### 5.1 核心结构

```go
type Hub struct {
    clients    map[uint]*Client
    register   chan registerRequest
    unregister chan *Client
    deliver    chan deliverRequest
    stop       chan struct{}
    done       chan struct{}
    stopOnce   sync.Once
}
```

只有 `Hub.Run` 的事件循环可以修改 `clients`。Client 和 Handler 通过公开方法提交请求，不直接持锁或访问连接表。

公开入口计划为：

```go
func NewHub() *Hub
func (h *Hub) Run()
func (h *Hub) Register(client *Client) bool
func (h *Hub) Unregister(client *Client)
func (h *Hub) SendToUser(userID uint, message ServerMessage) bool
func (h *Hub) Stop()
```

`Register` 和 `SendToUser` 使用单次响应通道返回事件循环的处理结果，避免“已写入 channel”被误认为“已经注册或投递”。Hub 已停止时直接返回 false。

### 5.2 注册和 connected

新 Client 在 Upgrade 成功后生成 UUID v4 `connection_id`。

首次注册：

1. Hub 将 `clients[userID]` 指向新 Client。
2. 向新 Client 发送首条 `connected`。
3. `connected.data` 固定为 `user_id` 和 `connection_id`。
4. 注册请求返回成功，Handler 再启动 Client 读写循环。

`connected` 使用服务端当前 Unix 毫秒时间，不接受客户端时间。

### 5.3 最新连接接管

同一用户第二条 IM 连接注册时：

1. 先把连接表替换为新 Client。
2. 向新 Client 排队 `connected`。
3. 向旧 Client 下发一个原子关闭命令：
   - 先写 `connection_replaced`；
   - `data.reason` 为 `connection_replaced`；
   - 再写 Close 帧，code 为 `4001`，reason 为 `connection_replaced`。
4. 注册请求返回成功。

替换顺序保证任何新投递都只进入新连接。旧连接通知是尽力而为；若旧连接已经断开或写入失败，直接关闭底层连接，不回退新连接。

### 5.4 防止旧连接误删

旧连接关闭后会异步提交 unregister。Hub 只有在以下条件同时满足时才删除当前映射：

```text
current.UserID == closing.UserID
current.ConnectionID == closing.ConnectionID
current == closing
```

因此旧连接晚到的 unregister 不能删除已经接管成功的新连接。

### 5.5 投递和慢连接

`SendToUser` 只向当前连接投递一个已经验证的服务端信封：

- 用户不在线：返回 false。
- Hub 已停止：返回 false。
- Client 发送缓冲区可写：排队并返回 true。
- Client 缓冲区已满：从连接表移除并关闭该连接，返回 false。

IM 不像游戏通道那样丢弃消息后依赖内存 seq 补推。后续聊天消息必须先持久化，再调用实时投递；断线恢复由数据库消息 seq 负责。

### 5.6 Stop

`Stop` 使用 `sync.Once`，允许 main 和测试安全重复调用：

1. 首次调用关闭 stop 信号。
2. Hub 事件循环停止接收新注册和投递。
3. 当前 Client 全部关闭。
4. 清空连接表。
5. 关闭 done 信号。
6. 所有 Stop 调用等待 done 后返回。

约束：main 必须先启动 `go imHub.Run()`，再暴露路由；停止阶段不再接受新请求。

## 6. IM Client

### 6.1 字段与写入所有权

```go
type Client struct {
    Hub          *Hub
    Conn         *websocket.Conn
    UserID       uint
    ConnectionID string
    send         chan []byte
    closeCommand chan closeCommand
    done         chan struct{}
    closeOnce    sync.Once
}
```

只有 writePump 可以调用 WebSocket 的写方法，避免数据消息、心跳和 Close 帧并发写入同一连接。

普通消息走 `send`；需要“先通知再关闭”的接管流程走独立 `closeCommand`。底层连接关闭由 `closeOnce` 保护，不关闭可能仍有生产者写入的 send channel，从而避免 send-on-closed panic。

### 6.2 readPump

固定参数沿用游戏通道：

- 最大文本消息：8192 字节。
- 写超时：10 秒。
- Pong 等待：60 秒。
- Ping 周期：54 秒。

读取规则：

1. 只接受文本消息；二进制消息以 WebSocket `1003` 关闭。
2. 超限消息由读取限制触发 `1009` 关闭。
3. 文本消息交给 `DecodeClientMessage`。
4. JSON 或顶层字段格式错误返回 `error / 1703`。
5. type、request_id 或 data 校验失败返回 `error / 1704`。
6. `ping` 返回同 request_id 的 `pong`。
7. 其他合法命名但未支持的 type 返回 `error / 1705`。

错误响应后连接保持可用；读取失败、关闭帧或网络错误才退出循环。

Ping 的 data 只允许省略、null 或空对象。Pong 不包含业务数据，使用服务端时间戳。

### 6.3 writePump

writePump 同时处理：

- send 中的文本消息；
- closeCommand 中的“可选通知 + Close 帧”；
- 周期性 WebSocket Ping 控制帧；
- done 信号。

任何写失败都关闭底层连接，使 readPump 退出并向 Hub 提交 unregister。

### 6.4 日志

日志只记录 user ID、connection ID、关闭类型和安全错误摘要。不得记录：

- 原始查询串；
- Access Token；
- 完整客户端消息正文；
- JWT 解析内部详情。

Gin 默认访问日志会包含 RawQuery，因此 Router 必须让 `/ws` 与 `/ws/im` 跳过默认访问日志；其他 REST 路径继续保留访问日志。对应测试使用哨兵 Token 验证日志中不存在查询凭据。

## 7. 握手 Handler

计划签名：

```go
func HandleWebSocket(
    hub *Hub,
    secret string,
    origins *realtime.OriginSet,
) gin.HandlerFunc
```

校验顺序：

1. Origin。
2. 查询参数 Access Token。
3. WebSocket Upgrade。
4. 创建带 UUID 的 Client。
5. 向 Hub 注册。
6. 启动 writePump 和 readPump。

升级前错误：

| 场景 | HTTP | 业务码 | message |
|---|---:|---:|---|
| Origin 不允许 | 403 | 1702 | `origin not allowed` |
| 缺少 Token | 401 | 1700 | `missing token` |
| Token 无效或过期 | 401 | 1701 | `invalid token` |

与游戏通道一致，Origin 拒绝优先于 Token 校验。升级后若 Hub 已停止，则用 `1013 / service unavailable` 关闭，不尝试返回 HTTP JSON。

## 8. Router 接入

用结构体替代当前单个位置参数：

```go
type WebSocketHandlers struct {
    Game gin.HandlerFunc
    IM   gin.HandlerFunc
}
```

`router.Setup` 接收 `WebSocketHandlers`：

- Game 非 nil 时注册 `GET /ws`。
- IM 非 nil 时注册 `GET /ws/im`。
- Router 不创建 Hub、不解析 Token、不持有连接状态。

所有现有测试把原来的 nil Handler 参数改为 `WebSocketHandlers{}`。增加路由测试确认两个端点分别调用对应 Handler，且公共 REST OpenAPI 契约不受 WebSocket 路由影响。

## 9. main 生命周期

main 在现有游戏 Hub 之外创建：

```go
imHub := imws.NewHub()
go imHub.Run()
```

路由组装：

```go
wsHandlers := router.WebSocketHandlers{
    Game: ws.HandleWebSocket(...),
    IM:   imws.HandleWebSocket(imHub, cfg.JWT.Secret, allowedOrigins),
}
```

收到退出信号后：

1. 停止 IM Hub。
2. 停止游戏 Hub。
3. 结束进程。

本块不扩展当前 HTTP Server 的优雅关闭模型；该问题如需改进单独进入工程优化，不能与 IM 连接语义混在同一提交。

## 10. 错误码

M2.0-C 启用：

| 错误码 | 类型 | 含义 |
|---:|---|---|
| 1700 | HTTP JSON | 缺少 Token |
| 1701 | HTTP JSON | Token 无效或过期 |
| 1702 | HTTP JSON | Origin 不允许 |
| 1703 | WS error | 信封 JSON 或顶层字段格式错误 |
| 1704 | WS error | type、request_id、data 或 Ping 载荷校验失败 |
| 1705 | WS error | 消息类型当前未支持 |

`1706` 处理器未注入和 `1707` 内部投递失败继续保留，等业务消息接入时启用，不在本块制造不可达分支。

WebSocket 应用关闭码：

| 关闭码 | reason | 使用场景 |
|---:|---|---|
| 4001 | `connection_replaced` | 同用户新 IM 连接接管旧连接 |
| 1003 | `unsupported data` | 客户端发送二进制消息 |
| 1009 | 标准超限原因 | 客户端消息超过 8 KiB |
| 1013 | `service unavailable` | Upgrade 后 Hub 已停止或无法注册 |

## 11. 测试设计

### 11.1 Hub 单元测试

- 首次注册保存连接并排队 connected。
- 同用户第二次注册后 map 指向新连接。
- 旧连接收到 connection_replaced 与 4001 关闭命令。
- 旧连接 unregister 不删除新连接。
- 当前连接 unregister 后用户离线。
- 不同用户互不覆盖。
- 在线用户投递成功，离线用户返回 false。
- 发送缓冲区满时关闭慢连接。
- Stop 关闭当前连接、清空 map、关闭 done，并可重复调用。

### 11.2 Client 单元与真实连接测试

- Ping 返回 Pong 并保留 request_id。
- malformed JSON 返回 1703。
- 空 type、非法 request_id 和非法 data 返回 1704。
- 未支持类型返回 1705。
- 二进制帧关闭为 1003。
- 超限消息关闭为 1009。
- 控制帧 Pong 延长读取期限。

### 11.3 Handler 与路由测试

- 允许 Origin + 合法 Token 成功升级，首条消息为 connected。
- 无 Origin 的客户端可升级。
- 缺 Token 返回 401/1700。
- 无效 Token 返回 401/1701。
- 不允许、null、多值 Origin 返回 403/1702。
- 不允许 Origin + 缺 Token 仍优先返回 1702。
- 同用户第二次真实连接使旧连接收到 replacement 并以 4001 关闭。
- 不同用户可同时在线。
- `/ws` 与 `/ws/im` 均注册且互不覆盖。

## 14. 风险与控制

- **重复关闭**：Client 底层关闭必须由 `sync.Once` 保护，Hub 不关闭仍可能被写入的 send channel。
- **旧连接误删**：unregister 必须同时比较指针和 connection ID。
- **并发写 WebSocket**：所有数据帧、Ping 和 Close 帧只能由 writePump 写。
- **Hub 停止死锁**：公开方法同时监听 done，Stop 使用 once 并等待事件循环。
- **慢连接失步**：缓冲区满即断开；后续持久化聊天使用数据库 seq 恢复。
- **业务范围泄漏**：除 Ping 外统一返回 1705，不创建假的聊天成功响应。
- **跨通道误替换**：游戏与 IM Hub 不共享连接表。
