## 三账号真实浏览器验收

使用 A（ID 23）、B（ID 24）、C（ID 25）三个隔离 Origin 的测试账号，创建群组 ID 4、群会话 ID 40。

- A 创建群并同时邀请 B、C；三端均可看到成员数、角色和群会话。A、B、C 各发送一条群消息，另外两端均实时收到带发送者的内容，发送端 pending 状态消除。
- 普通成员 B 无邀请、资料编辑、角色及移除入口；A 将 B 设为管理员后，B 可邀请及移除普通成员 C，但仍无资料编辑、角色调整或转让入口。
- B 移除 C 后，C 端群组立即消失；A 重邀 C 后群组恢复，C 可读取完整历史。C 主动退群、再次受邀入群也成功。
- C 离线期间 A 发送消息，C 重新打开页面后先显示未读，再补齐历史并归零。同账号打开第二页面，新页面连接正常，旧页面显示“账号已在其他页面建立了新的实时连接”。
- A 将群主转给 B；A/B 角色实时切换。B 修改群名称后，三端群资料和系统消息同步。A 转让后可主动退群，修复后的全新页面复验不再留下无角色群条目。

## 验收中修复的问题

1. 后端 CORS `Access-Control-Allow-Methods` 漏列 `PATCH`，浏览器预检导致“设为管理员”和编辑群资料失败。已放行 `PATCH`，新增预检回归测试，真实浏览器复验两个操作成功。
2. 自己退群时，REST 响应与 `group_member_changed` 可能交错：成员清理后，响应摘要被重新插入群列表，出现“2 人、无角色”残留。现固定退群前 group ID 做最终清理，并拒绝将 `current_user_role=null` 的摘要加入可见列表；新增竞态及无角色摘要测试，真实浏览器重邀并再次退群复验通过。
