# M2.5 主分支合并与真实验收清单

适用范围：M2.5-F 多人游戏页面、房间生命周期、流式行动、暂停/恢复、存档/读档、自动存档和结束态回看。

## 一、合并前置条件

- [ ] 当前分支已提交并推送远程。
- [ ] CI 全部通过：Go test、Go vet、Linux race、Vue 测试与构建、Python、迁移、OpenAPI、MySQL 8.4、Compose、Redis 双实例。
- [ ] PR diff 只包含 M2.5 代码、测试、验收 fixture 和文档，无临时日志、账号密码或生产配置。
- [ ] 已确认数据库迁移按顺序执行，重复执行不会破坏已有单人游戏和社交功能。
- [ ] 已确认回滚点为合并前主分支提交，必要时可回滚应用和迁移。

## 二、真实环境准备

使用测试环境或可回收数据，禁止直接使用生产玩家数据。

- [ ] 启动真实目标依赖：MySQL、Redis（双实例/总线配置）、MinIO、Go 服务、Python AI 服务和前端。
- [ ] 配置真实 DeepSeek/AI 凭据、Milvus/RAG、内部服务密钥和允许的 WebSocket Origin。
- [ ] 创建至少三个测试账号，准备一个多人脚本和三个不同角色。
- [ ] 记录版本号、分支提交 SHA、数据库迁移版本、AI 模型、Redis/MinIO 地址和测试开始时间。

## 三、三账号浏览器验收

每个账号使用独立浏览器会话，记录关键页面截图、网络错误和服务端日志。

### 开局与同步

- [ ] 账号 A 创建多人房间，账号 B/C 通过房间码加入。
- [ ] 三人分别选择不同角色并准备，房主开始游戏。
- [ ] 三端看到相同开场叙事、角色阵容、行动顺序、当前行动者和倒计时。

### 行动与权限

- [ ] 当前行动者提交一次真实 AI 流式行动，三端先看到临时片段，再看到同一条正式叙事和 seq。
- [ ] 非当前行动者的输入控件禁用。
- [ ] 使用接口或浏览器开发工具模拟非当前玩家提交，确认返回 403/业务错误，且回合水位不推进。
- [ ] 当前行动者主动跳过，确认只推进一次并同步到三端。
- [ ] 等待一次真实服务端超时，确认自动跳过、当前行动者和倒计时同步。

### 生命周期与存档

- [ ] 房主暂停，确认倒计时、行动提交和在途 AI 均停止。
- [ ] 恢复后确认创建新倒计时，旧 generation 的结果不会写入正式叙事。
- [ ] 创建手动存档，继续推进后读档，确认全体角色状态、叙事、行动顺序和当前行动者回到保存点，并保持 paused。
- [ ] 完成五个完整轮次，确认自动存档生成且回合文案与实际轮次一致。
- [ ] 在暂停或游戏中刷新浏览器、断开并恢复网络，确认成员未被移除，REST 快照能够恢复页面。

### 结束态

- [ ] 房主结束游戏，三端进入只读结束态。
- [ ] 刷新结束态页面，确认仍可读取最近记录和存档。
- [ ] 确认行动、跳过、暂停、恢复、读档等写操作均不可用。

## 四、结果判定

验收通过必须同时满足：

- 三端权威状态、叙事、seq、当前行动者和 deadline 一致。
- 非当前玩家无法推进水位；主动跳过和超时最多推进一次。
- 暂停、读档、刷新和重连不会混入旧 generation 的 AI 结果。
- 结束态可读但不可写，历史记录和存档可追溯。
- 服务端无未处理错误、重复完成事件、Redis 租约泄漏或数据库重复水位。

以下任一情况出现则暂停合并，先修复并重新跑完整清单：

- CI 有失败项或关键日志出现 panic、数据竞争、重复提交。
- 三端状态不一致、非当前玩家可插话、超时重复推进。
- 读档后角色/叙事/行动者不一致，或结束态刷新报房间不存在。
- 真实 AI、Milvus、Redis 双实例或 MinIO 依赖不可用且没有明确降级策略。
