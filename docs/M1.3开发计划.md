# M1.3 剧本系统开发计划

> **状态**：待开发  
> **制定日期**：2026-07-14  
> **目标**：打通“上传 PDF → 持久化 → 解析清洗 → 结构化切片 → 向量化 → 查询解析状态”的完整链路，为 M1.4 RAG 推理提供可用数据。

- 解析状态回写与失败处理。
- 剧本上传、列表、详情、删除前端界面。
- 自动化测试和全链路验收样本。

## 2. 开发前必须统一的约定

### 2.1 数据库字段

现有技术设计 SQL 与 Go 模型存在字段差异。实现时以迁移脚本为最终契约，并同步修正模型和文档：

| 语义 | 统一字段 |
|------|----------|
| 上传者 | `user_id` |
| MinIO 对象键 | `file_path` |
| 解析错误 | `parse_error` |
| 状态 | `uploading → parsing → ready / failed` |
| 软删除 | `deleted_at` |

`script_characters.attributes` 使用 JSONB；角色自动提取不阻塞 PDF 主解析链路，可在基础向量化成功后执行。

### 2.2 文件与接口约束

- 只接受 PDF，结合扩展名、Content-Type 和文件头校验。
- 默认最大文件大小 50 MiB，做成可配置项。
- MinIO 对象键格式：`scripts/{user_id}/{script_id}/{uuid}.pdf`。
- 上传成功返回 `202 Accepted`；客户端通过详情接口轮询状态，WebSocket 进度推送作为增强项。
- 用户只能查询、下载或删除自己的剧本。
- 删除剧本时同时清理 MinIO 对象和对应 Milvus 向量；任一外部清理失败要记录并可重试。

## 3. 实现顺序

### 步骤一：数据库与基础依赖

- [ ] 新增 `002_create_scripts.sql`。
- [ ] 新增 `003_create_script_characters.sql`。
- [ ] 统一技术设计 SQL、Go 模型和迁移字段。
- [ ] Go 引入 MinIO SDK，封装对象上传、删除和读取。
- [ ] 为文件大小、Bucket、解析超时补齐配置。

完成标准：迁移可在空数据库执行，Go 模型可正常 CRUD，MinIO Bucket 可自动确认或创建。

### 步骤二：Go 剧本 API

- [ ] 实现 `ScriptService`：校验文件、建记录、上传 MinIO、更新状态、触发 Python 解析。
- [ ] 实现上传、分页列表、详情和删除 Handler。
- [ ] 所有查询增加当前用户归属校验。
- [ ] 外部调用失败时将状态更新为 `failed` 并保存可读错误。
- [ ] 统一响应结构和剧本模块错误码（1200-1299）。

完成标准：四个剧本 REST 接口不再返回 501；未授权访问和非法 PDF 有明确错误。

### 步骤三：Python 解析管线

- [ ] `pdf_parser.py`：逐页提取文本，保留页码元数据，处理空白或扫描型 PDF。
- [ ] `text_cleaner.py`：规范空白、移除重复页眉页脚和页码，保留段落边界。
- [ ] `chunker.py`：优先按章节标题切片，控制 500-2000 字符并保留约 100 字符重叠。
- [ ] `embedder.py`：初始化 Embedding 模型和 Milvus Collection，批量写入向量。
- [ ] 写入元数据：`script_id`、章节、标题、页码、chunk 序号和原文。
- [ ] `script.py`：编排管线，返回真实结果；异常需结构化返回。

完成标准：给定可搜索 PDF，可在 Milvus 按 `script_id` 查到带元数据的文本块；重复解析不会产生重复数据。

### 步骤四：状态同步与前端

- [ ] 明确 Python → Go 状态回写机制；MVP 建议增加内部回调接口并进行共享密钥校验。
- [ ] 实现 `parsing`、`ready`、`failed` 状态更新。
- [ ] Dashboard 增加剧本列表、上传入口、进度/失败状态和删除操作。
- [ ] 增加剧本详情页，展示基础信息、预设角色和解析错误。
- [ ] 前端上传大小及类型校验，并避免重复提交。
- [ ] WebSocket `script_progress` 在基础轮询闭环稳定后接入。

完成标准：用户可以从 Web 页面完成上传，并看到状态最终变为成功或失败。

### 步骤五：测试与验收

- [ ] Go：Repository、Service、Handler 单元测试。
- [ ] Python：提取、清洗、切片及幂等写入测试。
- [ ] 准备三类样本：正常文本 PDF、含重复页眉页脚 PDF、扫描型/无文本 PDF。
- [ ] 执行 Go 测试、Vue 构建和 Python 测试。
- [ ] 使用 Docker Compose 完成全链路验收。

## 4. API 验收清单

| 方法 | 路径 | 预期 |
|------|------|------|
| `POST` | `/api/v1/scripts/upload` | 校验并保存 PDF，返回剧本记录与解析状态 |
| `GET` | `/api/v1/scripts?page=1&page_size=20` | 仅返回当前用户剧本，支持分页 |
| `GET` | `/api/v1/scripts/:id` | 返回详情、角色和解析状态 |
| `DELETE` | `/api/v1/scripts/:id` | 删除数据库记录并清理对象及向量 |
| `POST` | `/api/v1/ai/parse-script` | 执行解析和向量化，返回块数量等结果 |

## 7. 风险点

- 首次加载本地 Embedding 模型体积较大，开发环境可能受到网络、磁盘或内存限制。
- Python 当前依赖版本与 Docker 中 Milvus 版本需做兼容验证，必要时统一到同一 2.4 系列。
- 同步解析可能超过 Go 当前 60 秒 AI 超时，因此上传后解析应异步执行，状态通过轮询或进度消息读取。
- 删除涉及 PostgreSQL、MinIO、Milvus 三套存储，无法天然事务化，需要幂等清理和失败重试。
