## 2. 开发前必须统一的约定

### 2.1 数据库字段

现有技术设计 SQL 与 Go 模型存在字段差异。实现时以迁移脚本为最终契约，并同步修正模型和文档：

| 语义 | 统一字段 |
|------|----------|
| 上传者 | `user_id` |
| MinIO 对象键 | `file_path` |
| 解析错误 | `parse_error` |
| 向量片段数 | `chunk_count` |
| 状态 | `uploading → parsing → ready / failed` |
| 软删除 | `deleted_at` |

`script_characters.attributes` 使用 JSON；角色自动提取不阻塞 PDF 主解析链路，可在基础向量化成功后执行。

### 2.2 文件与接口约束

- 只接受 PDF，结合扩展名、Content-Type 和文件头校验。
- 默认最大文件大小 50 MiB，做成可配置项。
- MinIO 对象键格式：`scripts/{user_id}/{script_id}/{uuid}.pdf`。
- 上传成功返回 `202 Accepted`；客户端通过详情接口轮询状态，WebSocket 进度推送作为增强项。
- 用户只能查询、下载或删除自己的剧本。
- 删除剧本时同时清理 MinIO 对象和对应 Milvus 向量；任一外部清理失败要记录并可重试。

### 2.3 解析与状态同步约定

- Go 负责用户权限、剧本记录、文件校验、MinIO 写入和最终状态持久化。
- Python 根据 MinIO 对象键下载 PDF，不在服务之间传递容器本地文件路径。
- Python `POST /api/v1/ai/parse-script` 验证共享密钥，接受任务后快速返回，由后台任务执行解析。
- Python 通过 Go 内部接口回写 `ready` 或 `failed`，内部接口使用共享密钥鉴权。
- MVP 阶段先使用详情接口轮询状态；`script_progress` WebSocket 推送在基础闭环稳定后实现。
- 后台任务在进程重启时可能丢失，MVP 阶段通过“长时间停留在 parsing 的任务可重试”处理；持久化任务队列留待后续评估。

### 2.4 向量与 Milvus 约定

- Embedding 模型固定为 `BAAI/bge-large-zh-v1.5`。
- 该模型输出 1024 维向量，Milvus Collection 的 `embedding` 字段统一为 `FLOAT_VECTOR(1024)`。
- `pymilvus` 与 Milvus 服务端统一使用 2.4 系列，避免当前 2.3 SDK 与 2.4 服务端的兼容风险。
- Collection 使用 `script_chunks`，以 `script_id` 过滤，不为每个剧本单独创建 Collection。
- 重复解析前先删除该 `script_id` 的旧数据，保证写入幂等。
- 每个 Chunk 至少保存 `script_id`、`chunk_index`、`chapter_index`、`chapter_title`、`page_start`、`page_end` 和 `content`。

## 5. API 验收清单

| 方法 | 路径 | 预期 |
|------|------|------|
| `POST` | `/api/v1/scripts/upload` | 校验并保存 PDF，快速返回 `202` 和剧本解析状态 |
| `GET` | `/api/v1/scripts?page=1&page_size=20` | 仅返回当前用户剧本，支持分页 |
| `GET` | `/api/v1/scripts/:id` | 返回详情、角色和解析状态 |
| `POST` | `/api/v1/scripts/:id/retry` | 仅允许当前用户重新解析 `failed` 剧本 |
| `DELETE` | `/api/v1/scripts/:id` | 删除数据库记录并清理对象及向量 |
| `POST` | `/api/v1/ai/parse-script` | 接收解析任务并快速返回 |
| `POST` | `/api/v1/internal/scripts/:id/status` | Python 回写解析结果，仅允许共享密钥鉴权调用 |

### 5.1 完整验收条件

- 合法 PDF 上传后快速返回 `202 Accepted`。
- 非 PDF、超过 50 MiB、文件头与声明类型不符的上传被拒绝。
- 用户只能查询和删除自己的剧本。
- 正常文本 PDF 最终进入 `ready`。
- 扫描型、空白或不可解析 PDF 最终进入 `failed`，并包含可读错误。
- `failed` 剧本可重新提交解析；重复点击或非失败状态返回冲突。
- Milvus 可按 `script_id` 查询到带章节、页码和序号的文本块。
- 同一剧本重复解析不会产生重复向量。
- 删除后 MySQL、MinIO 和 Milvus 中不再保留有效数据。
- `go test ./...`、Python 测试、`npm run build` 和 Docker Compose 全链路检查通过。

## 8. 风险点

- 首次加载本地 Embedding 模型体积较大，开发环境可能受到网络、磁盘或内存限制。
- Python 当前 `pymilvus 2.3.6` 与 Docker 中 Milvus 2.4.0 存在版本差异，实现前统一到 2.4 系列。
- 技术设计中的 1536 维向量与当前 BGE 模型实际 1024 维不一致，实现和文档必须同步修正。
- 同步解析可能超过 Go 当前 60 秒 AI 超时，因此上传后解析必须异步执行。
- MVP 后台任务不具备持久化保证，服务重启时可能遗留 `parsing` 状态，需要提供超时重试能力。
- 删除涉及 MySQL、MinIO、Milvus 三套存储，无法天然事务化，需要幂等清理和失败重试。
- Python 下载 MinIO 文件及临时文件清理必须覆盖异常路径，避免磁盘空间持续增长。
