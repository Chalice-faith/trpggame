# TRPGGame 部署快速开始手册

> 发布请使用本文新增的「发布配置」章节；原有 `docker-compose.yml` 是开发入口。验收与模型密钥缺口见 [部署与摘要优化验收记录](部署与摘要优化验收记录.md)。

## 发布配置（2026-10-09）

复制 `.env.production.example` 为 `.env.production`，替换所有 `replace-with` 占位值。Go release 拒绝开发密钥：JWT 和共享密钥至少 32 字符，MySQL、Redis 和 MinIO 业务密码至少 16 字符，并要求显式 Origin。Python production 要求关闭 debug；`AI_ENABLED=true` 必须配置模型密钥，可使用 DeepSeek 或兼容平台。没有密钥时可用 `AI_ENABLED=false` 验证基础设施和 PDF 解析，AI 开场、行动及摘要生成不可用。

```bash
docker compose --env-file .env.production -f docker-compose.production.yml config --quiet
docker compose --env-file .env.production -f docker-compose.production.yml up -d --build
docker compose --env-file .env.production -f docker-compose.production.yml exec python-ai python -c "import urllib.request; print(urllib.request.urlopen('http://localhost:8000/ready').read().decode())"
```

这是独立配置，不能与开发 Compose 叠加。只发布 `127.0.0.1:8088` 静态 Nginx 入口，服务器需在前面配置 HTTPS/WSS 代理。`WEBSOCKET_ALLOWED_ORIGINS` 填浏览器完整 Origin。前端 REST 与双 WebSocket 使用当前站点，HTTPS 自动使用 WSS。数据库、Redis、Python、Milvus 和 MinIO 控制台不发布宿主机端口。

MinIO 管理员仅用于初始化；`minio-init` 创建剧本业务和 Milvus 用户，分别限制到 `MINIO_BUCKET` 和 `milvus-bucket`。Go/Python 共享业务凭据，Milvus 使用自己的凭据。已有卷更改账号/密码时必须同步更新服务端账号与权限；仅修改 env 不会轮换已有 MySQL 密码。升级前保留数据备份，初始化脚本不会清空旧桶。

Python `/health` 表示进程存活；`/ready` 实测 Redis、MinIO 桶、Milvus，并报告 embedding 加载状态与 AI `disabled` / `missing_key` / `configured_unverified`。配置模型密钥不等于供应商调用通过。生产默认预热 BGE，持久缓存位于 `model_cache` 卷；预热未完成或失败不会报告就绪。

迁移执行到 024，旧存档保留，摘要新增字段可空；024 支持 DDL 已成功而迁移记录尚未写入的恢复。不要通过删除摘要表或迁移记录回退，新模式房间应继续使用兼容归档/恢复的后端。

`GAME_MEMORY_NEW_ROOMS_ENABLED=false` 默认关闭新模式，可在验证后为新房间开启。worker 默认五次行动、轮询 2000ms、超时 50s、租约 90s，通过 Go `TRPG_GAME_SUMMARY_*` 配置。直接运行 Go 时新建开关名为 `TRPG_GAME_MEMORY_NEW_ROOMS_ENABLED`。

Python 预算配置为 `TRPG_AI_CONTEXT_INPUT_BUDGET`、`TRPG_AI_CONTEXT_WINDOW_TOKENS`、`TRPG_AI_CONTEXT_SAFETY_TOKENS`、`TRPG_AI_CONTEXT_SUMMARY_BUDGET`、`TRPG_AI_CONTEXT_KEY_EVENT_BUDGET` 和 `TRPG_AI_LLM_MAX_TOKENS`。直接启动可设置 env；Compose 已映射这些变量，默认值见发布模板。总预算采用保守 UTF-8 字节估算，日志记录估算和裁剪。

> 本文档说明如何在本机部署运行 TRPGGame，提供两种方式：
>
> 1. **Docker Compose 一键部署**（推荐，全栈启动）
> 2. **本地开发部署**（基础设施用 Docker，应用服务本地跑）
>
> 文末附「最小可跑方案」，只启动用户系统与游戏 REST 闭环，不依赖 AI 服务。

## 一、服务清单与端口

项目由 3 个应用服务 + 5 个基础设施组成：

| 服务 | 技术栈 | 默认端口 | 是否必需 |
|------|--------|---------|---------|
| vue-frontend | Vue 3 + Vite | 5173 | 是（界面） |
| go-backend | Go + Gin | 8080 | 是（业务后端） |
| python-ai | Python + FastAPI | 8000 | 可选（AI 叙事 / 剧本解析） |
| MySQL | 8.x | 3306 | 是（持久化） |
| Redis | 7.x | 6379 | 是（缓存 / 运行态） |
| MinIO | 对象存储 | 9000 / 9001 | 是（PDF 文件存储） |
| Milvus | 向量数据库 | 19530 / 9091 | 可选（RAG 检索，依赖 etcd + MinIO） |
| etcd | 元数据存储 | 2379 | 仅 Milvus 需要 |
| Nginx | 反向代理 | 80 / 443 | 可选（生产） |

> **关键依赖关系**：`go-backend` 启动时会**依次连接 MySQL、Redis、MinIO，任一连不上都会直接退出**。因此无论哪种部署方式，这三个服务都必须先就绪。

## 二、Docker Compose 一键部署（推荐）

### 前置要求

- [Docker](https://docs.docker.com/engine/install/) + [Docker Compose](https://docs.docker.com/compose/install/)（Docker Desktop 已内置）

### 1. 准备环境变量

```bash
# 在项目根目录
cp .env.example .env
```

编辑 `.env`，至少填写：

| 变量 | 说明 | 是否必填 |
|------|------|---------|
| `DEEPSEEK_API_KEY` | DeepSeek 的 API Key | 否（缺省则 AI 推理不可用） |
| `DEEPSEEK_API_BASE` | Chat Completions 基础地址，如 `https://openrouter.ai/api/v1`；不要包含 `/chat/completions` | 默认 `https://api.deepseek.com` |
| `DEEPSEEK_MODEL` | 平台实际提供的模型 ID | 默认 `deepseek-v4-flash` |
| `AI_TIMEOUT_SECONDS` | Go → Python HTTP 超时（秒） | 默认 60 |
| `LLM_TIMEOUT_SECONDS` | Python → 模型 HTTP 超时（秒） | 默认 120 |
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码 | 建议改强密码 |
| `MYSQL_PASSWORD` | 业务账号 `trpg` 的密码 | 建议改强密码 |
| `INTERNAL_SHARED_SECRET` | Go ↔ Python 内部回调密钥 | 建议改随机值 |
| `VITE_API_BASE_URL` | 浏览器访问的 Go REST 地址 | 默认 `http://localhost:8080` |
| `VITE_WS_URL` | 浏览器游戏 WebSocket 地址 | 默认 `ws://localhost:8080/ws` |
| `VITE_IM_WS_URL` | 浏览器 IM WebSocket 地址 | 默认 `ws://localhost:8080/ws/im` |

OpenRouter 等兼容平台仍使用上述配置名。需要支持 Chat Completions、SSE 及 `tools/tool_calls`。本机当前凭据保存在忽略的 `.env` / `python-ai/.env`，`key.txt` 已从 Git 和根 Docker 构建上下文排除，示例配置不含真实密钥。原生启动 Python 时使用 `TRPG_AI_DEEPSEEK_API_KEY`、`TRPG_AI_DEEPSEEK_API_BASE`、`TRPG_AI_DEEPSEEK_MODEL` 和 `TRPG_AI_LLM_TIMEOUT`。

2026-10-09 已用 `nvidia/nemotron-3-ultra-550b-a55b:free` 通过普通响应、流式响应、工具调用及 231 字摘要的接口冒烟。摘要耗时约 80 秒；本机开发 `.env` 因此设 Go HTTP 超时 180 秒、Python 模型超时 150 秒、摘要 worker 超时 150 秒和租约 210 秒，租约必须大于 worker 超时。模板保留原默认值，开发与发布 Compose 都支持覆盖。接口通过不等于 50 轮长局和目标部署已验收，证据见 [B 验收记录](M3.1-B验收记录.md)。

### 2. 启动全栈

```bash
docker compose up -d
```

首次启动会拉取 MySQL、Milvus 等镜像并构建 go-backend / python-ai / vue-frontend 三个镜像，耗时取决于网络。

### 3. 仅启动基础设施（本地开发时用）

本地开发时不需要用容器跑应用服务，只需基础设施：

```bash
# 最小基础设施（用户系统 + 游戏 REST 即可运行）
docker compose up -d mysql redis minio

# 完整基础设施（含 AI 所需）
docker compose up -d mysql redis minio etcd milvus
```

### 4. 启动后访问

| 服务 | 地址 |
|------|------|
| 前端 | http://localhost:5173 |
| Go 后端 | http://localhost:8080 |
| Python AI | http://localhost:8000/health |
| MinIO 控制台 | http://localhost:9001（账号密码见 `.env`，默认 `minioadmin/minioadmin`） |

### 5. 常用命令

```bash
docker compose logs -f go-backend python-ai   # 查看日志
docker compose down                           # 停止并移除容器（数据卷保留）
docker compose down -v                        # 停止并删除数据卷（清空数据）
```

## 三、本地开发部署

适用于需要改代码、热重载调试的场景。基础设施仍建议用 Docker 起，应用服务本地跑。

### 前置要求

- [Go 1.22+](https://go.dev/dl/)
- [Node.js 18+](https://nodejs.org/)
- [Python 3.11+](https://www.python.org/)（仅跑 AI 服务时需要）

### 1. 启动基础设施

```bash
docker compose up -d mysql redis minio        # 最小
# 如需 AI 功能：
docker compose up -d mysql redis minio etcd milvus
```

### 2. 执行数据库迁移

```bash
npm ci
npm run db:migrate
```

- 默认读取根目录的迁移环境变量，并兼容 `TRPG_DATABASE_*` 配置。
- `docker compose up` 时由一次性的 `migrate` 服务自动执行；本地直接启动 Go 后端前应先运行上述命令。

### 3. 启动 Go 后端

```bash
cd go-backend
go mod download
go run cmd/server/main.go
```

- 默认读取 [configs/config.yaml](../go-backend/configs/config.yaml)，连 `localhost` 的 MySQL / Redis / MinIO。

- 开发 MinIO 已统一为 `minioadmin/minioadmin`。本地 Go 不会自动读取根目录 `.env`；Compose 密码修改后需显式设置 `TRPG_DATABASE_PASSWORD`、`TRPG_MINIO_ACCESSKEY`、`TRPG_MINIO_SECRETKEY`。Python 使用 `TRPG_AI_*`，两端共享密钥必须一致。

### 4. 启动 Python AI 服务（可选）

> 需要 Milvus 已启动、且能下载 Embedding 模型（`BAAI/bge-large-zh-v1.5`，约 1.3GB）。

```bash
cd python-ai
python -m venv venv
# Windows:
venv\Scripts\activate
# macOS / Linux:
source venv/bin/activate

pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

- AI 服务环境变量前缀为 `TRPG_AI_`（见 [app/config.py](../python-ai/app/config.py)），默认连 `localhost` 的 Milvus / Redis / MinIO。
- 不启动 AI 服务时，注册登录、游戏 REST 接口照常可用，仅 AI 叙事与剧本解析不可用。

### 5. 启动 Vue 前端

```bash
cd vue-frontend
npm install
npm run dev
```

- 前端 API / WebSocket 地址由 [vue-frontend/.env](../vue-frontend/.env) 配置，默认分别为 `http://localhost:8080`、`ws://localhost:8080/ws` 与 `ws://localhost:8080/ws/im`。
- Compose 可在根目录 `.env` 中覆盖 `VITE_API_BASE_URL`、`VITE_WS_URL`、`VITE_IM_WS_URL`；这些值必须是浏览器可访问的公开地址，不能填写容器内部服务名。

## 四、最小可跑方案（仅用户系统 + 游戏 REST）

如果只想快速看到界面、跑通注册登录和游戏后端闭环，无需 AI 服务与 Milvus：

### 步骤

```bash
# 1. 只起三个基础设施容器
docker compose up -d mysql redis minio

# 2. 启动 Go 后端
cd go-backend && go run cmd/server/main.go

# 3. 启动前端（另开一个终端）
cd vue-frontend && npm install && npm run dev
```

浏览器打开 http://localhost:5173 即可注册登录。

### 已知限制

- ✅ 可用：注册 / 登录 / JWT 鉴权 / 个人信息 / 游戏 REST 闭环（快速开始、行动、存档、读档、暂停、结束）
- ✅ 可用：用户搜索 / 好友申请 / 好友列表 / IM 在线状态（需要 MySQL、Redis、MinIO 与 Go 后端）
- ❌ 不可用：剧本 PDF 上传解析、AI 叙事、骰子检定（依赖 Python AI + Milvus + `DEEPSEEK_API_KEY`）

## 五、关键配置说明

### Go 后端配置优先级

`环境变量(TRPG_ 前缀) > configs/config.yaml > 内置默认值`，实现见 [internal/config/config.go](../go-backend/internal/config/config.go)。

常用环境变量：

| 环境变量 | 对应配置 | 默认值 |
|---------|---------|--------|
| `TRPG_DATABASE_HOST` | MySQL 地址 | localhost |
| `TRPG_DATABASE_USER` / `TRPG_DATABASE_PASSWORD` | MySQL 账号 | trpg / trpg123 |
| `TRPG_DATABASE_DBNAME` | 数据库名 | trpggame |
| `TRPG_REDIS_ADDR` | Redis 地址 | localhost:6379 |
| `TRPG_MINIO_ENDPOINT` | MinIO 地址 | localhost:9000 |
| `TRPG_MINIO_ACCESSKEY` / `TRPG_MINIO_SECRETKEY` | MinIO 账号 | minioadmin / minioadmin |
| `TRPG_AI_BASEURL` | Python AI 地址 | http://localhost:8000 |
| `TRPG_JWT_SECRET` | JWT 签名密钥 | dev-secret（生产必改） |
| `TRPG_WEBSOCKET_ALLOWEDORIGINS` | 浏览器 WebSocket Origin 白名单 | 本地 Vue 与 Nginx 地址 |

`TRPG_WEBSOCKET_ALLOWEDORIGINS` 使用逗号分隔的完整 `http` / `https` Origin，不接受通配符和带路径 URL。游戏和 IM WebSocket 均已启用该检查；正式部署必须加入实际前端 Origin，否则浏览器连接会收到 `403 / 1508`（游戏）或 `403 / 1702`（IM）。无 Origin 的原生客户端仍需通过 JWT，游戏连接还需通过房间权限校验。

### 凭据对齐（重要）

`docker-compose.yml` 内的基础设施默认凭据与 `config.yaml` 是**自洽**的：

- MySQL：`trpg / trpg123`，库 `trpggame`
- MinIO：`minioadmin / minioadmin`

如果你**手动 `docker run` 启动基础设施**（而非 `docker compose`），请确保容器凭据与 `config.yaml`（或用环境变量覆盖）一致，否则 Go 后端会连接失败。

## 六、常见问题（FAQ）

### Q1：Go 后端启动即退出，日志报 `Failed to connect database/Redis/MinIO`

Go 后端启动时**强依赖** MySQL、Redis、MinIO 三者全部就绪。请确认：

1. 三个容器已启动：`docker compose ps`
2. 端口可达：本机能访问 `localhost:3306 / 6379 / 9000`
3. 凭据一致（见上文「凭据对齐」）

### Q2：手动 `docker run` 的 MySQL 没有 `trpg` 用户和 `trpggame` 库

若启动 MySQL 容器时未设置 `MYSQL_USER` / `MYSQL_DATABASE`，需手动创建：

```sql
CREATE DATABASE IF NOT EXISTS trpggame CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER IF NOT EXISTS 'trpg'@'%' IDENTIFIED BY 'trpg123';
GRANT ALL PRIVILEGES ON trpggame.* TO 'trpg'@'%';
FLUSH PRIVILEGES;
```

> 建表无需手动做，先在项目根目录执行 `npm ci && npm run db:migrate`。

### Q3：表是自动建的吗？

是。根目录的 `npm run db:migrate` 按固定顺序执行 `database/migrations/001~017`，使用 MySQL advisory lock 防并发，并记录在 `schema_migrations` 表。Docker Compose 会在启动 Go 后端前自动运行它。

### Q4：Windows + WSL2 场景，本地应用连不上容器端口？

确认 WSL2 的 `localhostForwarding` 开启（默认开启）。Windows 侧访问 `localhost:<端口>` 应能转发到 WSL 内的 Docker 容器。可用 `netstat -ano | findstr LISTENING | findstr 3306` 验证监听状态。

### Q5：AI 对话 / 剧本解析不可用？

检查：

1. Python AI 服务是否启动（http://localhost:8000/health）
2. Milvus + etcd 是否启动（`docker compose up -d etcd milvus`）
3. `.env` 或容器环境变量里是否配置了 `DEEPSEEK_API_KEY`

### Q6：生产部署注意事项

- 通过环境变量注入所有密钥（`TRPG_*` / `TRPG_AI_*`），**不要提交明文配置**。
- 将 `TRPG_SERVER_MODE=release`、`TRPG_JWT_SECRET` 换成强随机值。
- 使用最小权限数据库账号，替换默认 `trpg` / `minioadmin` 等弱凭据。
- Nginx 已在 `docker-compose.yml` 中作为反向代理（`/api/*`、`/ws/*` → Go 后端），生产可基于此配置 HTTPS。

### Q7：部署后如何验收多人游戏？

先确认 MySQL、Redis、MinIO、Milvus、Go、Python AI、Vue/Nginx 和真实 DeepSeek 配置均健康，再按 [M2.5 主分支合并与真实验收清单](./M2.5主分支合并与真实验收清单.md) 使用三个独立账号执行开局、流式行动、权限拒绝、主动/超时跳过、暂停/读档、自动存档、断线恢复和结束态回看。验收证据需脱敏，禁止记录 API key、JWT 或生产玩家数据。
